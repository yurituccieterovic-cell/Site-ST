# Roteiro — Ep02: A Ação como Unidade Fundamental
**Série**: Inteligência em Camadas — Do Signo à Frequência  
**Duração**: ~5 min | **Cenas**: 7 | **Tom**: conceitual-prático

---

## CENA 1 — ABERTURA (0:00–0:30)
*Fundo escuro. Um ponto de luz surge. Ele se move. Deixa um rastro.*

**NARRAÇÃO**:
"O que é a menor unidade de um sistema inteligente?
Não é o dado. Não é o algoritmo. Não é o modelo.
É a *ação*."

---

## CENA 2 — O QUE É UMA AÇÃO? (0:30–1:30)
*Animação: sete círculos aparecem ao redor de um nó central chamado AÇÃO.*

**NARRAÇÃO**:
"Toda ação real tem sete dimensões:

ESPAÇO — onde acontece no sistema  
TEMPO — quando acontece  
AUTOR — quem ou o que executa  
OBJETIVO — para que serve  
CAUSA — o que motivou  
CONSEQUÊNCIA — o que muda depois  
PERSPECTIVA — o ponto de vista de quem age

Uma ação sem pelo menos três dessas dimensões declaradas
não é uma ação — é ruído."

*Animação: os círculos giram ao redor do nó central. Três deles ficam em destaque.*

---

## CENA 3 — DADOS SÃO SIGNOS (1:30–2:30)
*Fluxo de dados em tela. Câmera aproxima: cada dado tem uma sombra — o signo.*

**NARRAÇÃO**:
"Aqui está algo que a maioria dos sistemas ignora:
dados não existem por si mesmos.

Um dado é um *signo* — ele aponta para algo além de si.
O número '37' não significa nada sozinho.
Dentro de um sistema de saúde, significa febre.
Dentro de um velocímetro, significa limite de velocidade.

Quando uma IA trata dados como objetos — e não como signos —
ela perde exatamente o que torna a informação útil: o *contexto*."

---

## CENA 4 — A CADEIA SEMIÓTICA (2:30–3:15)
*Animação de cadeia linear, cada elo se ilumina na sequência.*

**NARRAÇÃO**:
"Em um sistema que opera com signos, existe uma cadeia:

DADO → é lido
PENSAMENTO → é processado
REPRESENTAÇÃO → é gerado um signo novo
AÇÃO → esse signo se materializa
MEMÓRIA → a ação é registrada

Cada etapa importa. Pular qualquer uma cria lacunas
que se acumulam como erros sistêmicos invisíveis."

---

## CENA 5 — O PROTOCOLO (3:15–4:00)
*Interface limpa. Uma ação aparece com os campos preenchidos.*

**NARRAÇÃO**:
"Um sistema bem projetado declara cada ação com clareza:

[DADO LIDO] → qual informação foi recebida  
[REPRESENTAÇÃO] → como ela foi interpretada  
[AÇÃO] → o que foi feito  
[FERRAMENTA] → com o que foi feito  
[CONSEQUÊNCIA] → o que mudou

Isso não é burocracia. É *rastreabilidade*.
É a diferença entre um sistema que aprende e um que repete."

---

## CENA 6 — EXEMPLO REAL (4:00–4:45)
*Antes e depois. Sistema sem protocolo vs. sistema com protocolo.*

**NARRAÇÃO**:
"Sistema sem protocolo:
Usuário digita 'preciso de ajuda'. Sistema responde.
Nenhum registro do porquê, do contexto, do que mudou.

Sistema com protocolo:
[DADO LIDO]: 'preciso de ajuda' em contexto de erro de login  
[REPRESENTAÇÃO]: usuário frustrado, falha técnica identificada  
[AÇÃO]: sugerir reset de senha + abrir ticket  
[CONSEQUÊNCIA]: problema resolvido, padrão identificado

Mesma resposta. Resultado diferente na aprendizagem do sistema."

---

## CENA 7 — ENCERRAMENTO (4:45–5:00)
*Onda pulsando. Logo.*

**NARRAÇÃO**:

Por que toda IA precisa saber para onde está indo antes de agir."
